 0. Recommended approach (how to structure the rewrite)
 Do not keep growing UserSubscriptionService with all BRD logic. Extract a new freeze package and leave thin legacy
 wrappers on the old endpoints until mobile cutover.

 Create under order-backend (match existing package style):
 az.fitnest.order.service.freeze.* az.fitnest.order.model.entity.SubscriptionFreeze*
 az.fitnest.order.model.enums.FreezeStatus az.fitnest.order.controller.SubscriptionFreezeController
 az.fitnest.order.dto.freeze.* az.fitnest.order.repository.SubscriptionFreeze* az.fitnest.order.event.FreezeOutbox*


 Copy patterns from:
 • Idempotent durable outbox: payment-backend PaymentOutboxService + OutboxRelay (copy structure into order, do not call
     payment).
 •   Scheduled jobs: existing @Scheduled methods already on UserSubscriptionService — move freeze finalize into its own
     worker class.
 •   gRPC status: UserSubscriptionGrpcServiceImpl — today it forwards translated UI status; catalog gates need canonical
     raw status.
 •   Migrations: folder exists src/main/resources/db/migration/ (V4 present) but Flyway is NOT enabled; either enable
     Flyway like identity-backend OR keep using ddl-auto: update + checked-in SQL for ops. Prefer enabling Flyway +
     V5__subscription_freeze_brd.sql.

 How to edit (pattern, not full implementation):

 • DELETE/replace the hardcode in freezeSubscription:
 Do NOT:

 • Do not keep freezing ALL remaining days (current dead-code path daysToFreeze = availableFreezeDays).
 • Do not open UX success without commit returning freezeId/startAt/planEndAt.
 Stub to remove (production today):

 BadRequestException("error.freeze_not_allowed_for_plan"); }

 How to rewrite those methods:
 • freezeSubscription(userId) (legacy): either reject with deprecation message OR map to commit with days=available
     (temporary). Prefer mobile switches to new API.
 •   New flow in SubscriptionFreezeService: getEligibility → preview(days) → commit(previewId, idempotencyKey).
 •   Eligibility reads entitlement balances + subscription status ACTIVE + endAt>now + no ACTIVE freeze + catalog booking conflict
     check.
 •   Preview: validate integer days 1..available; compute planEndAt=now+D*86400; projectedExpiry=endAt+D*86400; store preview
     with expectedVersion + TTL; return previewId. Preview must NOT write financial/limit commits.
 •   Commit: lock subscription row (pessimistic or version check); re-validate; insert SubscriptionFreeze ACTIVE; reservedDays+=D;
     subscription.status=FROZEN; sync legacy frozenAt/unfreezesAt/frozenDaysUsed for old clients; write audit+outbox; return 201.
 •   Resume-preview: compute elapsedSeconds, usedDays=ceil(elapsed/86400) min 1, returnedDays, expiryAfter; quote
     TTL=min(60s, next 24h boundary).
 •   Resume: if planEndAt reached → route to finalize COMPLETED; if usedDays changed → 409 PREVIEW_CHANGED; else
     ENDED_EARLY, status ACTIVE, adjust entitlement consumed/reserved, extend endAt by actual elapsed seconds (not full
     requested days).
 •   Legacy unfreezeSubscription: replace calendar-day refund math with call into
     SubscriptionFreezeService.resumeImmediate(userId) using same BR-08 formula.
 •   Error keys to add in messages_*: error.freeze.invalid_days, limit_exceeded, already_frozen, booking_conflict, preview_changed,
     not_frozen (map to HTTP 422/409).
 •   Also add missing keys already thrown today: error.freeze_not_allowed_for_plan, error.freeze_days_exhausted.

 New controller endpoints (add; do not only edit old ones):
 GET /api/v1/subscriptions/{id}/freeze POST /api/v1/subscriptions/{id}/freeze/preview POST
 /api/v1/subscriptions/{id}/freezes // Idempotency-Key header POST /api/v1/freezes/{id}/resume-preview POST

 before any write.

 BE-ORD-4 — Worker + lazy finalize (replace hourly autoUnfreeze)

 How to edit (pattern, not full implementation):

 • Move auto-unfreeze OUT of UserSubscriptionService into FreezeFinalizeService.completeIfDue(freeze).
 • Worker selects SubscriptionFreeze where status=ACTIVE AND planEndAt <= now (not only Subscription.unfreezesAt).

     freeze extends endAt; if endAt passed mid-freeze, finalize first or extend consistently with BRD.
 •   Race: SELECT FOR UPDATE / @Version on SubscriptionFreeze; if already terminal, return existing result (AC-09).

 7. Suggested PR order (backend only)
 • PR1 order: V5 schema + entities + FreezeTierPolicy + entitlement on assign (BE-ORD-1/2).
 • PR2 order: Freeze services + new controller + legacy wrappers + messages (BE-ORD-3/5).
 • PR3 order: finalize worker + autoFinish fix + outbox (BE-ORD-4/7).
 • PR4 order: upgrade/revoke terminate (BE-ORD-6) + proto raw status.
 • PR5 catalog: GymEntrance + Reservation + optional conflict API (BE-CAT-1/2) — depends on PR4 gRPC.
 • PR6 gateway routes (BE-GW-1) — can land with PR2.
 • PR7 notifications templates (BE-NOTIF-1) — after outbox shape stable.
 • PR8 payment terminate on refund (BE-PAY-1) — after order RPC exists.

 8. What NOT to rewrite
 • Reservation freezeSession / restoreSession / frozenSessions / consumeFrozenSession — visit escrow.
 • PackageOption DB schema for freeze_days — not the BRD source of truth.
 • landing-frontend / admin write toggles — out of this backend pack (admin read later).
 • Mobile apps — separate tickets; backend must keep legacy /freeze+/activate until cutover flag.

 9. BA blockers that change these edits
 • Backfill existing ACTIVE paid → whether BE-ORD-2 job runs at all.
 • Trial exclusion → assignSubscriptionToUser skip condition.
 • Booking conflict = APPROVED only vs PENDING too → catalog conflict query filter.
 • FitMarket revoke vs block-new-only → BE-CAT-3 scope.
 • Refund always cancels membership → whether BE-PAY-1 is required or order-admin-only.
